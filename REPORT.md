# Отчёт по тестовому заданию САП КОД

**Время:** ориентировочно 1,5–2 часа, включая изучение задания, доработку кода, запуск тестов и подготовку отчёта. Точное время не фиксировал.

## 1. Что было сломано

При проверке возникала проблема с незакрытыми SQLite-соединениями в тестах: в Windows это могло приводить к ошибке `PermissionError` при удалении временной директории с базой данных. Также требовалось проверить, что обработчик корректно отличает новые заявки от дубликатов, валидирует входные данные и не создаёт лишние уведомления.

## 2. Что исправлено

- Добавил проверку типа события и обязательных полей `source`, `external_id`, `customer`, `message`.
- Добавил удаление пробелов по краям строк перед сохранением и сравнением.
- Обеспечил уникальность заявки по паре `(source, external_id)` с помощью уникального индекса SQLite.
- Настроил обработку повторных событий: возвращается ID существующей заявки, исходные данные не перезаписываются.
- Обеспечил создание уведомления только для новой заявки.
- В тестах использовал `contextlib.closing`, чтобы явно закрывать SQLite-соединения и избегать блокировки временных файлов.

## 3. Как проверено

Запустил тесты командой:

```powershell
python -m unittest discover -s tests -v
```

Результат последнего запуска:

```text
Ran 8 tests in 0.183s

OK
```

Все 8 тестов прошли успешно. Проверены создание заявки и уведомления, повторная обработка дубликата, уникальность с учётом источника, валидация полей, обрезка пробелов, сохранение первоначальных данных и работа с той же базой после повторного подключения.

Дополнительные тесты на событие `None` и различие источников `Telegram` и `telegram` пока не запускались, поэтому не указываю их как проверенные.

## 4. AI-инструменты

Использовал **ChatGPT (GPT-6)** для разбора требований задания, анализа логики обработчика и SQLite, поиска причины проблемы с закрытием соединений, рекомендаций по исправлению тестов и подготовки отчёта.

Предложения AI использовал как помощь при разработке. Результат тестирования проверил самостоятельно: запустил `unittest` в терминале и убедился, что все 8 тестов завершились со статусом `OK`.


## 5. Оставшиеся ограничения и риски

- Подтверждено прохождение 8 тестов из текущего набора.
- Дополнительные тесты на событие не-словарь и чувствительность `source` к регистру пока не запускались.
- Ошибки самой SQLite, например невозможность открыть базу данных, отдельно не преобразуются в ответ `invalid` и могут приводить к исключению.
- Успешное прохождение текущих тестов не гарантирует отсутствия всех возможных ошибок.
